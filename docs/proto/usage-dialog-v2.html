① 为什么不会再错位

  • 对齐全部交给布局引擎：固定宽 cell（width=10ch）+ 弹性占位（flexGrow / marginLeft:auto），零手工空格拼接
  • CJK 测宽偏差只会整体平移，不会再出现某行多一格、某行少一格的错行
  • 全部原语均来自已验证代码：CacheDialog 的 marginLeft:auto、宿主的 flexGrow spacer

② 相比 v1 砍掉的东西

  • 点阵大字：背景色块在真实终端碎裂（vision 确认），改为 bold + accent 色承担视觉权重
  • 双线外框 ╔═╗：宿主 dialog 自带面板底色与居中定位，手画边框是纯粹的错位源
  • 进度条：按需求取消；表格占比条、指标微条全部移除
  • 表格竖线 │：不再手拼，列距由弹性布局拉开，更接近 opencode 原生对话框风格

③ 布局解剖（对齐的实现方式）

label 固定 10ch
flexGrow 弹性空隙
value 右对齐
模型列 flexGrow（长名不截断）
请求数 10ch
Token 12ch

④ 切 tab 不重算指标 · Bug 修复方案

  • 根因：旧指标区用「数字索引 For + 回调体内提前取值」，切窗口时索引数组 [0..5] 相同 → Solid 判定无变化 → 行内容永不重建；明细表是对象引用 For → 每次新对象触发重建，所以只有表在刷
  • 修复：指标 / 总量 / 表格全部改为对象 For 或内联 map，stats 一变全区域重算
  • 验证：实施时配 headless 渲染测试——切窗口后断言指标数值与表格同步变化

⑤ 色彩与交互

accent 总量 ≥85% 命中 ≥70% <70% muted 标签
  • tab 点击切换（‹选中› accent，其余 muted）；esc 关闭；错误态纯文本 + 点击重试
  • Top 10 + 其他模型 · N 聚合行（dim）；缓存写入仅 >0 时显示
  • 面板 60ch 填满宿主 medium 容器（水平居中），高度 ~26 行（垂直观感趋中）
